# Release and reproducible builds

**Version:** 1.0 · 2026-11-26
**Applies to:** build phase B10 (`BUILD-ROADMAP.md` §B10), `Tech-Stack.md` §11.

Nothing in this file is a secret. The keystore and its passwords live outside the
repository and are never printed by a build.

## The owner's signing keystore

The keystore is created once, by the owner, and kept outside the working tree:

```sh
mkdir -p ~/.openhealth
keytool -genkeypair -v -keystore ~/.openhealth/openhealth-release.jks \
  -alias openhealth -keyalg RSA -keysize 4096 -validity 10000
```

The four values then go into `.env.local` at the repository root, which `.gitignore`
already excludes:

```sh
OH_KEYSTORE=/home/<you>/.openhealth/openhealth-release.jks
OH_KEYSTORE_PASSWORD=...
OH_KEY_ALIAS=openhealth
OH_KEY_PASSWORD=...
```

The Gradle build reads them from the environment. With them absent, `assembleRelease`
still builds an **unsigned** release APK for inspection; the signing step is skipped rather
than falling back to the debug key, so an unsigned artefact can never be mistaken for a
shippable one.

Back the keystore up somewhere safe. Losing it means a new application signing identity and
an app that cannot be updated in place on the store.

## Artefacts

```sh
set -a; . ./.env.local; set +a
./gradlew :app-android:assembleRelease :app-android:bundleRelease
```

| Artefact | Path | Notes |
|---|---|---|
| Play APK | `app-android/build/outputs/apk/play/release/app-android-play-release.apk` | R8-minified, resource-shrunk, signed |
| F-Droid APK | `app-android/build/outputs/apk/fdroid/release/app-android-fdroid-release.apk` | Play-Services-free: no ML Kit, no Google Data Transport |
| Play bundle | `app-android/build/outputs/bundle/playRelease/app-android-play-release.aab` | For a Play track |
| F-Droid bundle | `app-android/build/outputs/bundle/fdroidRelease/app-android-fdroid-release.aab` | For a store that takes an AAB |

Check the signature without the password:

```sh
$ANDROID_HOME/build-tools/<version>/apksigner verify --print-certs \
  app-android/build/outputs/apk/play/release/app-android-play-release.apk
```

Store metadata is in Fastlane's standard layout, `fastlane/metadata/android/en-US/`.
`privacy_policy_url.txt` holds a bracketed placeholder until the owner hosts
`docs/privacy-policy.md`.

## Two store flavours

Both flavours use the Apache-2.0 ZXing decoder. ML Kit was removed in B6 (ADR 0011) because
its transitive Google Data Transport is a telemetry path; the F-Droid build must keep
building with no Play Services at all, and CI assembles both debug variants on every PR.

## Reproducible-build notes

The project aims for a build another person can repeat, not a byte-identical one:

- **Pinned toolchain.** `gradle/wrapper/gradle-wrapper.properties` pins the Gradle
  distribution with its SHA-256; `gradle/libs.versions.toml` pins every dependency;
  `docs/adr/0003-pinned-versions.md` records why.
- **No dynamic versions.** No `+`, no `latest.release`, no SNAPSHOT in the catalogue.
- **Committed baseline profile.** `app-android/src/main/baseline-prof.txt` is generated by
  `:tools:benchmark`'s `BaselineProfileGenerator` and committed, so a build does not depend
  on a device being present.
- **No build-time downloads beyond declared repositories.** Repositories are `google()`,
  `mavenCentral()` and `gradlePluginPortal()`, declared once in `settings.gradle.kts` with
  `FAIL_ON_PROJECT_REPOS`.
- **F-Droid.** The F-Droid build uses the same wrapper and catalogue, builds
  `fdroidRelease` with no Google repository artefacts at runtime, and signs with F-Droid's
  own key. A `.jks` in the tree would make the build fail review; none exists.

Known non-determinism, stated rather than hidden: R8 output can differ between JDK and R8
patch releases, and the APK's signing block carries timestamps. Rebuild the same commit with
the same JDK 21 and AGP and compare `apksigner verify --print-certs` and the class list;
byte-for-byte equality is not claimed.
